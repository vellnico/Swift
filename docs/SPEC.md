# Swift — спецификация и план

Версия спецификации: 1.2 (2026-11-08). Источник истины по продукту. Расхождения с реализацией исправляются в этом файле в том же PR.

---

## 1. Продукт

Swift — панель для одного сервера, на котором работает Xray-core. Аудитория — владелец сервера, который раздаёт доступ себе и близким. Лимитов трафика, скорости и сроков нет: установил, создал пользователей, раздал ссылки.

Главные качества, по которым оценивается результат:
1. **Удовольствие от настройки.** Красивый строгий интерфейс, выразительные анимации, понятные пояснения к каждому параметру, рекомендуемое значение всегда отмечено.
2. **Лёгкость и скорость.** Панель занимает меньше 30 МБ RAM в простое и запускается меньше чем за 1 с. Интерфейс отвечает мгновенно, первая загрузка весит меньше 150 КБ gzip.
3. **Надёжность.** Установка одной командой, Xray автоматически перезапускается после падения, сертификаты продлеваются сами.

### Вне рамок MVP
Лимиты трафика, скорости и сроков; статистика по пользователям; оплата и тарифы; мульти-нода; Telegram-бот; 2FA; протоколы кроме VLESS и Hysteria2.

## 2. Пользовательские сценарии

1. **Установка.** `bash <(curl -fsSL .../install.sh)` → вопрос «есть домен?» → в терминале чётко выводятся URL панели, логин и пароль. При установке сразу создаются профили по умолчанию.
2. **Первый вход.** URL → экран входа → дашборд. Мастера настройки нет: всё уже работает.
3. **Добавить человека.** «Пользователи» → «+» → имя → карточка с QR-кодом и ссылкой подписки → «Скопировать» или «Поделиться».
4. **Добавить протокол.** «Профили» → «+» → выбор протокола → «Создать». Порт, SNI и ключи подобраны автоматически. Ручная настройка — по кнопке «Настроить вручную».
5. **Подключение у пользователя.** Ссылка подписки открывается в браузере → страница с QR и кнопкой «Добавить в Hiddify» → импорт; российские сайты уже идут напрямую.
6. **Обслуживание.** Дашборд показывает состояние сервера и Xray. Обновление Xray — одна кнопка с автоматическим откатом при ошибке.

## 4. Архитектура

```
┌──────────────────────── swift (один процесс, systemd) ─────────────────────────┐
│ HTTPS :<random_port>/<random_path>/   → SPA + /api + /api/events (SSE)         │
│ HTTPS :<sub_port>/s/<token>           → сервер подписок                        │
│                                                                                │
│ web ──▶ services ──▶ store (SQLite, WAL)                                        │
│                 └──▶ xray.Manager ──▶ Supervisor ──▶ xray (дочерний процесс)   │
│                                  └──▶ gRPC API 127.0.0.1:<api_port>            │
│ jobs: sysstat (2 с), cert renew (24 ч), geo update (24 ч), xray release check  │
└────────────────────────────────────────────────────────────────────────────────┘
```

- **Применение изменений.** Добавление и удаление пользователя выполняется через `HandlerService.AlterInbound` (Add/RemoveUserOperation) без рестарта Xray. Изменение профилей или сертификатов приводит к генерации нового конфига, затем `xray run -test`, затем атомарной замене файла и рестарту Xray. Если проверка не прошла, старый конфиг остаётся, ошибка показывается в UI.
- **Supervisor.** Перезапускает Xray при падении с backoff 1 → 2 → 4 → … → 30 с; если процесс проработал больше 60 с, backoff сбрасывается. Каждое событие пишется в журнал и рассылается по SSE.
- **Сверка при старте.** Swift генерирует конфиг из БД и запускает Xray; БД — единственный источник истины.
- **SSE `/api/events`.** Через него рассылаются метрики сервера, статус Xray, ход применения изменений и события журнала. Фронтенд не опрашивает сервер по таймеру.
- **Порты.** Порт панели и порт подписок выбираются при установке. По умолчанию они разные, но можно использовать один.

## 5. Модель данных

```sql
CREATE TABLE admins (
  id INTEGER PRIMARY KEY,
  username TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,            -- argon2id, PHC-строка
  created_at INTEGER NOT NULL
);

CREATE TABLE sessions (
  id TEXT PRIMARY KEY,                    -- 32 байта, base64url
  admin_id INTEGER NOT NULL REFERENCES admins(id) ON DELETE CASCADE,
  expires_at INTEGER NOT NULL,
  ip TEXT, user_agent TEXT
);

CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);
-- server_address, domain, panel_port, panel_path, sub_port, sub_path,
-- language, routing_preset, geo_source, xray_version

CREATE TABLE profiles (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('vless_reality_vision','vless_reality_xhttp','hysteria2')),
  port INTEGER NOT NULL,
  enabled INTEGER NOT NULL DEFAULT 1,
  manual INTEGER NOT NULL DEFAULT 0,      -- 1 = пользователь менял параметры вручную
  params_json TEXT NOT NULL,              -- типизированные параметры, см. §6
  position INTEGER NOT NULL,              -- порядок в подписке
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);

CREATE TABLE users (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  sub_token TEXT NOT NULL UNIQUE,         -- 24 байта, base64url
  vless_uuid TEXT NOT NULL,
  hy2_password TEXT NOT NULL,             -- 24 байта, base64url
  enabled INTEGER NOT NULL DEFAULT 1,
  note TEXT NOT NULL DEFAULT '',
  created_at INTEGER NOT NULL
);

CREATE TABLE certificates (
  id INTEGER PRIMARY KEY,
  kind TEXT NOT NULL CHECK (kind IN ('acme','self_signed')),
  domain TEXT,                            -- NULL для self-signed на IP
  cert_path TEXT NOT NULL, key_path TEXT NOT NULL,
  sha256_hex TEXT NOT NULL,               -- отпечаток листового сертификата
  not_after INTEGER NOT NULL,
  last_error TEXT
);

CREATE TABLE events (
  id INTEGER PRIMARY KEY,
  ts INTEGER NOT NULL,
  level TEXT NOT NULL CHECK (level IN ('info','warn','error')),
  source TEXT NOT NULL,                   -- xray, certs, geo, auth, update
  message_key TEXT NOT NULL,              -- ключ i18n
  params_json TEXT NOT NULL DEFAULT '{}'
);
```
Каждый пользователь получает все включённые профили. Журнал `events` хранит последние 1000 записей.

## 6. Профили

### 6.1 Типы
| kind | Транспорт | Порт по умолчанию | Сертификат |
|---|---|---|---|
| `vless_reality_vision` | TCP, `flow: xtls-rprx-vision`, Reality | 443/tcp | не нужен |
| `vless_reality_xhttp` | XHTTP, Reality | 8443/tcp | не нужен |
| `hysteria2` | QUIC (UDP), TLS | 443/udp | ACME или self-signed |

VLESS на 443/tcp и Hysteria2 на 443/udp сосуществуют. Конфликты портов проверяются отдельно для TCP и UDP; порт панели и порт подписок тоже участвуют в проверке.

### 6.2 Автоматическое создание — «одна кнопка»
Пользователь выбирает только тип профиля. Swift сам:
- выбирает свободный порт: сначала из рекомендуемых (443, 8443, 2053), затем случайный из 20000–60000;
- для Reality генерирует пару ключей x25519 и 3 `shortIds`, выбирает `dest`/`serverNames` из встроенного списка SNI (`internal/xray/sni.go`), проверяя каждый кандидат с сервера: TLS 1.3, X25519, H2, ответ меньше 1 с; берётся первый подходящий;
- для XHTTP генерирует случайный `path`, `mode: auto`;
- для Hysteria2 берёт сертификат домена или self-signed и генерирует пароль Salamander. Обфускация Salamander включена по умолчанию, потому что это единственный тип, который поддерживают все целевые клиенты.

### 6.3 Ручная настройка
Форма со всеми параметрами профиля. Обычные поля видны сразу, редкие спрятаны в «Дополнительно». У каждого поля есть:
- короткое пояснение в 1–2 строки: что делает параметр и когда его менять;
- бейдж «Рекомендуется» у оптимального значения и кнопка «Вернуть рекомендуемое»;
- валидация на лету.

Пояснения хранятся в i18n (`profiles.fields.<name>.hint`). Список полей по типам задаётся схемой в `internal/xray/profile_schema.go` и отдаётся фронтенду через `/api/profiles/schema`, чтобы формы строились из одного источника.

Изменения применяются кнопкой «Применить». В процессе показывается анимированный статус: проверка → перезапуск → готово или ошибка с текстом.

### 6.4 Версия Xray и схема конфига
- Версия фиксируется в `internal/xray/version.go`. Генератор пишется именно под неё.
- Схема конфигурации Hysteria2 в Xray менялась между релизами 2026 года (например, порт-хоппинг переехал в `finalmask` / UDP-маску `udphop` в 26.9.9). Перед реализацией этапа 3 сверь генератор с документацией и исходниками зафиксированной версии.
- Формат отпечатка: в ссылке `hysteria2://` параметр `pinSHA256` и в Xray-JSON `pinnedPeerCertSha256` — hex в нижнем регистре (Xray 26.10.31 разбирает оба как hex, допускает двоеточия; base64 отвергает — см. §15). Клиенты на Xray падают на base64. Покрыть тестом.

## 7. Пользователи и подписки

### 7.1 Пользователи
- Создание (имя, заметка), удаление с отменой (toast «Удалено · Отменить», 5 с), включение и выключение, перевыпуск ссылки (новый `sub_token`, `vless_uuid`, `hy2_password`).
- Карточка показывает имя, статус, QR подписки, кнопки «Копировать», «Поделиться» (Web Share API) и «Ссылки по профилям» (QR и ссылка для каждого профиля отдельно).

### 7.2 Share-ссылки
```
vless://<uuid>@<host>:<port>?type=tcp&security=reality&pbk=<pub>&fp=chrome&sni=<sni>&sid=<sid>&flow=xtls-rprx-vision#<name>
vless://<uuid>@<host>:<port>?type=xhttp&security=reality&pbk=<pub>&fp=chrome&sni=<sni>&sid=<sid>&path=<path>&mode=auto#<name>
hysteria2://<password>@<host>:<port>/?sni=<sni>&obfs=salamander&obfs-password=<p>&insecure=0&pinSHA256=<hex>#<name>
```
Для домена с ACME `pinSHA256` не добавляется. Имена `#<name>` берутся из шаблона «Swift · <профиль>».

### 7.3 Сервер подписок
`GET /s/<token>` на порту подписок. Формат выбирается по `User-Agent`; параметр `?format=` имеет приоритет.

| Клиент (UA содержит) | Формат | Раздельное туннелирование |
|---|---|---|
| `Hiddify`, `sing-box`, `SFA`, `SFI`, `SFM` | **sing-box JSON** — основной формат | `route.rule_set` + правила в конфиге |
| `Happ` | base64-список ссылок | заголовок `routing` (профиль Happ в base64) |
| `v2rayNG` | Xray-JSON (массив конфигов) | правила в `routing` конфига |
| `v2RayTun` и всё остальное | base64-список ссылок | не передаётся; инструкция на странице подписки |
| Браузер (`Mozilla` без признаков клиента) | HTML-страница подписки | — |

Заголовки ответа: `profile-title: base64:<...>`, `profile-update-interval: 12`, `content-disposition: attachment; filename="swift"`, `profile-web-page-url` (ссылка на HTML-страницу). `subscription-userinfo` не отправляется: лимитов нет.

Отключённый пользователь получает валидную пустую подписку (не 404), чтобы клиент не удалял профиль. Неизвестный токен получает 404 без тела.

**Hiddify — приоритетный клиент.** Генератор sing-box JSON и HTML-страница проверяются на Hiddify в первую очередь. На этапе 5 обязательно:
1. проверить, как текущая версия Hiddify импортирует sing-box JSON по ссылке подписки и не перетирает ли свои настройки маршрутизации поверх наших;
2. проверить, как sing-box в Hiddify проверяет self-signed сертификат Hysteria2 (поле отпечатка или `certificate` в `tls` outbound) и что для этого нужно в JSON;
3. если что-то не работает — зафиксировать в §15 и предложить альтернативу (например, отдавать Hiddify base64 и полагаться на его встроенную опцию региона).

### 7.4 Страница подписки (HTML)
Отдельный лёгкий бандл (`web/sub`, < 30 КБ gzip) в том же дизайне:
- имя пользователя, большой QR, кнопка «Скопировать ссылку»;
- кнопки «Добавить в Hiddify» (deeplink `hiddify://import/<url>#<name>`), «Добавить в Happ», «Добавить в v2rayNG» — с определением платформы и ссылками на загрузку приложения;
- блок «Как включить "российское напрямую"» только для v2RayTun: 3–4 шага;
- язык определяется по `Accept-Language` (RU/EN), иначе — язык панели, выбранный при установке (`settings.language`, по умолчанию английский).

Deeplink-схемы клиентов могут меняться; на этапе 5 сверь их с текущей документацией клиентов.

## 8. Раздельное туннелирование

Один пресет в MVP: **«Российское напрямую»** — российские домены и IP, а также приватные сети идут напрямую, остальное через VPN. Переключатель в разделе «Маршрутизация»: «Российское напрямую» / «Всё через VPN». Поле для своих доменов — в бэклоге.

Источник геоданных: `runetfreedom/russia-v2ray-rules-dat` — в стандартных geo-файлах категория `ru` распознаётся не полностью. Точные имена категорий и URL rule-set'ов сверь с репозиторием на этапе 8 и запиши в `internal/routing/presets.go`.

| Формат | Реализация |
|---|---|
| sing-box (Hiddify) | `route.rule_set` с удалёнными `.srs` (geoip ru, geosite ru) → `outbound: direct`; `ip_is_private` → direct; DNS: удалённый DoH для proxy, локальный для direct |
| Xray-JSON (v2rayNG) | `routing.rules`: `geosite:<ru-категория>`, `geoip:ru`, `geoip:private` → direct; `domainStrategy: IPIfNonMatch` |
| Happ | заголовок `routing`: JSON-профиль (`DirectSites`, `DirectIp`, `Geoipurl`, `Geositeurl`, `GlobalProxy: "true"`) в base64 |

Golden-тесты на все три формата с включённым и выключенным пресетом.

## 9. Сертификаты

- **Есть домен** (выбор в `install.sh` или позже в настройках): Let's Encrypt через lego, челлендж HTTP-01 (порт 80 временно) с fallback на TLS-ALPN-01. Сертификат используется панелью, подписками и Hysteria2.
- **Только IP:** сертификат Let's Encrypt на IP-адрес сервера (профиль `shortlived`, около 160 часов, HTTP-01 на порту 80; IP-сертификаты Let's Encrypt выдаёт с января 2026). Браузер и клиенты ему доверяют, поэтому подписка скачивается по HTTPS без исключений, а Hysteria2 обходится без pin. Если Let's Encrypt недоступен (закрыт порт 80, частный адрес), используется self-signed ECDSA P-256 на 10 лет со случайным CN и `pinSHA256` для Hysteria2; панель повторяет попытку получить IP-сертификат каждые 6 часов.
- **Продление:** задача каждые 6 ч продлевает ACME-сертификат, если до истечения меньше 30 дней (у IP-сертификата — меньше 3 дней). Истёкший IP-сертификат, который не удалось продлить, заменяется self-signed до следующей удачной попытки. Новый сертификат подхватывается панелью без рестарта (`tls.Config.GetCertificate`), Xray перезапускается. Ошибки пишутся в журнал и выводятся баннером на дашборде.
- Смена режима «IP ↔ домен» в настройках перевыпускает ссылки Hysteria2 (меняются `sni` и pin). Перед сменой UI предупреждает, что клиентам нужно обновить подписку.

## 10. Дизайн

### 10.1 Идея
Swift — стриж, самая быстрая птица, которая почти не садится на землю. Отсюда образ: тёмное ночное небо, серебристый блеск крыла, точная механика. Интерфейс должен ощущаться как дорогой инструмент — часы, камера Leica, полированная сталь на чёрном бархате, а не как типовая админка. Цель — чтобы в панель хотелось возвращаться и задерживаться.

Пять правил, которые отличают Swift от шаблонных панелей:
1. **Строго чёрно-белый.** Только нейтральная шкала от «Обсидиана» до «Фарфора». Ни одного цветного акцента, цветных статусов и цветных иконок. Роль акцента играет свет: белый текст, серебряный блик, яркость линий.
2. **Материал, а не плоскость.** Глубокий чёрный фон с едва заметным зерном, как бархат или матовая плёнка. У поверхностей есть тонкая светлая кромка сверху, как у обработанного металла. Теней почти нет: глубина передаётся светом.
3. **Типографика несёт характер.** Широкий экспрессивный шрифт для чисел и заголовков, спокойный гротеск для интерфейса. Крупные цифры на дашборде — главное украшение экрана.
4. **Одна подпись.** Единственный запоминающийся эффект — «серебряный блик»: мягкая полоса света, которая проходит по логотипу при входе и по главной кнопке при подтверждении действия. Он не повторяется везде, поэтому остаётся особенным.
5. **Тишина вокруг.** Много воздуха, мало рамок, никаких декоративных подписей капслоком, цифровых маркеров «01 / 02» и стрелок «→» в кнопках. Каждый элемент на экране что-то сообщает.

| Блик | `#FFFFFF` | только для серебряного блика и кромок на максимуме |

Линии и кромки задаются белым с прозрачностью, а не серым цветом, чтобы они одинаково выглядели на любой поверхности. QR-коды — чистый чёрный `#000` на чистом белом `#FFF` в отдельной подложке: так камеры считывают их надёжно.

### 10.3 Шрифты
| Роль | Шрифт | Использование |

Перед этапом 1 проверь актуальные версии и лицензии и запиши их в `web/public/fonts/LICENSES.md`.

### 10.5 Компоненты
- **Главная кнопка:** фарфоровая заливка, обсидиановый текст Onest 600, высота 40 px. При подтверждении действия по ней проходит серебряный блик. На экране не больше одной главной кнопки.
- **Вторичная кнопка:** прозрачная, кромка `--line-strong`, текст фарфор. **Тихая кнопка:** только текст серебром, при наведении — фарфор.
- **Поле ввода:** `--surface-2`, кромка `--line`; в фокусе кромка становится `--line-strong`, а фон светлеет на одну ступень. Подпись над полем, пояснение под полем мелким серебром.
- **Бейдж «Рекомендуется»:** таблетка с кромкой `--line-strong`, текст `--t-micro` фарфором, маленькая звёздочка из линий. Кнопка «Вернуть рекомендуемое» — тихая.
- **Переключатель:** в выключенном состоянии — пустая таблетка с кромкой; во включённом — фарфоровая заливка и обсидиановый бегунок, перелёт пружиной.
- **Карточка:** `--surface-1`, `--edge`, радиус `--radius-surface`, внутренние отступы 20 px. При наведении кромка становится `--edge-lit`, больше ничего не меняется.
- **Toast:** снизу по центру, `--surface-3` с `--edge-lit`; действие «Отменить» — тихая кнопка фарфором.
- **Ошибка:** инвертированный блок (фарфор, текст обсидиан) с иконкой и текстом, что случилось и что сделать. **Предупреждение:** блок с кромкой `--line-strong` и иконкой.
- **Иконки:** lucide, толщина линии 1.5 px, размер 18 px, цвет серебро, у активных — фарфор.
- **Логотип:** силуэт стрижа из двух серповидных крыльев одной линией 1.5 px плюс надпись «Swift» шрифтом Unbounded 400. Рисуется в SVG вручную на этапе 1; простой, читаемый в 20 px.

### 10.6 Движение
Движение отвечает на действия человека и показывает, что изменилось. Фоновой анимации ради анимации нет.

- **Серебряный блик (подпись Swift):** диагональный градиент от прозрачного через `rgb(255 255 255 / 0.18)` обратно в прозрачный проходит слева направо за `--dur-gleam` с `--ease-in-out`. Где используется: логотип на экране входа (один раз после загрузки), главная кнопка после успешного действия. Больше нигде.
- **Вход в панель:** после успешного логина форма уходит вниз с fade, логотип переезжает пружиной на своё место в сайдбаре, контент дашборда проявляется одним слитным движением за 420 мс. Это единственная оркестрованная последовательность в приложении.
- **Переходы между разделами:** crossfade 220 мс со сдвигом на 6 px; фарфоровая полоска активного пункта навигации переезжает пружиной.
- **Модальные окна и bottom sheet:** выезжают пружиной, фон затемняется и слегка размывается (`backdrop-filter: blur(8px)`); на телефоне закрываются жестом вниз.
- **Кнопки:** нажатие сжимает до 0.97; асинхронное действие показывает тонкий спиннер вместо текста при сохранённой ширине, затем галочку.
- **Живые числа на дашборде:** значение перетекает через `Spring`, цифры не мигают. Спарклайны — фарфоровая линия 1.5 px с заливкой от белого 10 % до прозрачного; новая точка въезжает справа плавно.
- **Копирование:** значение на мгновение подсвечивается кромкой, иконка превращается в галочку, на Android срабатывает короткая вибрация (`navigator.vibrate(10)`, если доступна).
- **Статус Xray:** работает — сплошная фарфоровая точка с медленной пульсацией света раз в 3 с; перезапуск — серебряное кольцо, которое вращается; остановлен — перечёркнутое кольцо и текст «Остановлен».
- **QR:** проявляется из размытия за 420 мс.
- **Появление списков:** только при первой загрузке раздела, 20 мс между элементами, не больше 8 элементов с задержкой; при изменении данных анимируются только изменившиеся элементы.
- Пресеты пружин в `web/src/lib/motion.ts`: «мягкая» `{ stiffness: 0.12, damping: 0.85 }` для перемещений, «точная» `{ stiffness: 0.3, damping: 0.9 }` для мелких элементов.
- `prefers-reduced-motion`: пружины и блик отключаются, остаётся fade 140 мс; статусы различимы по форме.
- Анимируются только `transform`, `opacity` и `filter`. Цель — 60 fps на среднем телефоне.

### 10.9 Тон текста
Спокойный, точный, без восклицаний и маркетинга. Действия называются глаголом, который описывает результат: «Создать профиль» → toast «Профиль создан». Ошибки объясняют, что случилось и что сделать, и не извиняются. Пустые состояния приглашают к действию: «Здесь появятся люди, которым вы дадите доступ. Добавьте первого». Никаких подписей капслоком над заголовками, разделителей «·» в метаданных там, где хватает переноса строки, и стрелок в кнопках.

### 10.10 Принципы UX
- Деструктивные действия — через «Отменить» в toast, а не через диалог подтверждения. Исключения: смена порта панели, смена режима «IP ↔ домен» и обновление Xray — там диалог с объяснением последствий.
- Пустые состояния — с иллюстрацией из тонких линий (силуэт стрижа в полёте) и одной кнопкой действия.
- Командная палитра в MVP не делается. Горячие клавиши: `/` — поиск, `n` — создать в текущем разделе, `Esc` — закрыть.
- Все интерактивные элементы доступны с клавиатуры, видимое кольцо фокуса `--focus-ring`. Контраст текста не ниже WCAG AA (серебро на графите — проверить на этапе 1).
- Технические значения (ключи, токены, IP) набираются JetBrains Mono и копируются по клику.


## 11. Безопасность и установка

### 11.1 Панель
- Доступ только по `https://<host>:<panel_port>/<panel_path>/`. Порт случайный (20000–60000), путь — 16 символов `[a-z0-9]`. Любой другой путь получает 404 с пустым телом; поведение такое же, как у несуществующего сервера.
- Логин — 8 случайных символов, пароль — 20 символов. Хэш argon2id (m=64 МБ, t=3, p=2).
- Сессия хранится в cookie: `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/<panel_path>/`, TTL 14 дней с продлением при активности.
- CSRF защищается заголовком `X-Swift-CSRF` (double-submit) для всех запросов, кроме GET.
- Rate limit входа: 5 неудач за 10 минут с одного IP приводят к блокировке на 15 минут, событие пишется в журнал.
- Заголовки ответов: CSP без `unsafe-inline` для скриптов, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`.

### 11.2 CLI
```
swift serve
swift admin show          # URL, логин (без пароля)
swift admin reset         # новый пароль, вывод в терминал
swift version [--xray]    # версия Swift и Xray; --xray — только версия Xray
swift setup               # подготовка сервера для install.sh (идемпотентно)
swift ports               # порты для файрвола: «tcp 443», «udp 443»…
swift db backup <file>    # копия БД через VACUUM INTO
```

### 11.3 `install.sh`
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/<owner>/swift/main/scripts/install.sh)
```
0. Первым вопросом спросить язык: «Language / Язык: 1 English, 2 Русский» (по умолчанию English, флаг `--lang en|ru`, при `--non-interactive` — English). На этом языке говорит установщик, и он же сохраняется как язык панели по умолчанию (`swift setup -lang`).
1. Проверить root, Debian 11+ / Ubuntu 20.04+, архитектуру `amd64`/`arm64`, systemd.
2. Спросить: «Есть домен, указывающий на этот сервер? [y/N]». Если да — ввести домен и проверить, что его A-запись совпадает с IP сервера.
3. Скачать релиз `swift` и зафиксированную версию Xray с GitHub Releases и **проверить SHA256**.
4. Разложить файлы: `/usr/local/bin/swift`, `/usr/local/lib/swift/xray`, geo-файлы — в `/usr/local/lib/swift/`, `/etc/swift/`, `/var/lib/swift/swift.db`.
5. Сгенерировать учётные данные, порты, путь и сертификат; создать профили по умолчанию: VLESS Reality Vision 443/tcp и Hysteria2 443/udp.
6. Включить BBR (флаг `--no-bbr` отключает).
7. Открыть порты в `ufw`/`firewalld`, если они активны.
8. Установить `swift.service` (`Restart=always`, `RestartSec=3`, `LimitNOFILE=1048576`) и запустить его.
9. Вывести рамку с URL, логином и паролем — чётко, с пустыми строками вокруг, плюс предупреждение «сохраните пароль».
10. Флаги: `--update` (бэкап БД через `VACUUM INTO` и замена бинарника), `--uninstall`, `--version <tag>`, `--domain <d>`, `--lang en|ru`, `--non-interactive`. Повторный запуск идемпотентен.

### 11.4 Обновление Xray из панели
Настройки → «Xray» показывает текущую и последнюю доступную версию (GitHub API, проверка раз в сутки). Сценарий: скачать новую версию → проверить SHA256 → прогнать `xray run -test` с текущим конфигом → заменить бинарник → перезапустить. Если Xray не поднялся за 10 с, вернуть старый бинарник. Новая версия может не совпадать со схемой генератора, поэтому мажорные изменения показываются с предупреждением, а бэкап старого бинарника хранится до следующего обновления.
